# Micro-CMS v1

- 実施日: 2026-10-29
- 対象: [Hacker101 CTF の Micro-CMS v1](https://ctf.hacker101.com/ctf)
- 結果: **4/4 提出済み**。CTF 一覧でも 4/4 を確認
- 注: 課題インスタンスのホスト名とフラグ全文は公開しない

## Flag0: 非公開ページの編集画面

1. トップページには `/page/1` と `/page/2` のリンクだけがあった。
2. ページ番号を確認すると、`/page/4` は 403 Forbidden だった。
3. 既存ページの「Edit this page」から編集 URL が `/page/edit/<番号>` と分かった。
4. `/page/edit/4` を開くと、閲覧不可ページ「Private Page」の本文が編集フォームに表示され、フラグが含まれていた。
5. フラグを提出し、ヒント画面で Flag0 が Found になったことを確認した。

閲覧を拒否するページの内容を編集画面が表示していた。既存ページは変更していない。

## Flag1: 編集 URL の引用符

1. 通常の `/page/1` に引用符を追加した `/page/1%27` は 404 だった。
2. 編集側の `/page/edit/1` に引用符を追加し、`/page/edit/1%27` を開いた。
3. 応答本文にフラグが表示された。提出後、CTF 一覧で 4/4 を確認した。

引用符を含む値に対し、編集側の処理が異常な応答とフラグを返した。内部実装を確認していないため、SQL インジェクションかどうかは断定しない。

## Flag2: タイトルの HTML 注入

1. 検証用ページを作成し、タイトルに次を入れた。

   ```html
   H101 test <img src=x onerror="document.body.dataset.h101=1">
   ```

2. 個別ページの見出しではタグがエスケープされていたが、トップページに戻るとサイトのダイアログにフラグが表示された。
3. そのフラグを提出し、ヒント画面で Flag2 が Found になったことを確認した。

個別ページと一覧ページでタイトルの扱いが異なっていた。再訪時にもダイアログが出たため、提出後は検証用ページのタイトルを通常の「H101 test」に戻した。

## Flag3: Markdown 本文のイベント属性

1. 検証用ページの本文を次のように変更して保存した。

   ```html
   <img src=x onerror="document.body.dataset.h101=1">
   ```

2. 表示ページの生成 HTML では `img` と `onerror` が残り、`img` に `flag` 属性が追加されていた。
3. その属性のフラグを提出し、ヒント画面で Flag3 が Found になったことを確認した。

検証後、本文も通常の「Rendering check completed.」に戻した。
