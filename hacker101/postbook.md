# Postbook — 調査記録

- 実施日: 2026-10-29
- 対象: [Hacker101 CTF の Postbook](https://ctf.hacker101.com/ctf)
- 状態: **6/7 の Flag を提出済み**（最終の一覧確認は後で実施）
- 課題インスタンスのホスト名、セッション情報、フラグ値、仮の認証情報は公開しない

## 初期確認

1. CTF 一覧で Postbook は 0/7。完了済みの Micro-CMS v2 を終了して Postbook を起動した。
2. 起動ページの「The level is being set up, one moment please」表示が続き、待機がタイムアウトした。後に本人が画面の表示を知らせ、再開時に Postbook のトップ画面を確認できた。
3. トップ画面には Sign in / Sign up と、公開・非公開の投稿を作れるという説明がある。
4. Sign up 画面は仮の一時的な資格情報のみ使うよう案内し、ユーザー名には小文字のみ許可すると表示する。入力欄が 2 個あり、Submit ボタンは未入力時に無効。
5. 最初の入力では画面操作が中断したが、本人の追加指示によって再接続した。入力途中の状態を確認し、演習用の仮アカウントの登録・ログインに成功した。
6. 1Password の確認ダイアログが一時的に入力を遮った。保存済みの資格情報は使っていない。

## Flag0: 既存ユーザーの弱いパスワード

公式ヒントは「`user` のパスワードが非常に簡単」と示した。`user/user` は失敗したが、`user/password` でログインに成功し、ホーム画面に Flag0 が表示された。フラグを提出し、CTF から受理メッセージを確認した。

## Flag1: 非公開投稿の IDOR

ホーム画面の公開投稿リンクは `view.php&id=1`（admin）と `view.php&id=3`（user）だった。間の `view.php&id=2` を直接開くと、admin の「Dear diary...」という非公開投稿と Flag1 が表示された。フラグを提出した。

## Flag2: 他ユーザー投稿の編集権限確認漏れ

自分の投稿には `edit.php&id=3` という編集リンクがある。`edit.php&id=1` に変更して admin の公開投稿を開くと編集フォームが表示された。内容を変えずに「Save post」を押したところ、保存成功画面に Flag2 が表示された。フラグを提出した。

## Flag3: 隠れた投稿 ID

公開 writeup にある「189 × 5」というヒントを手掛かりに、`view.php&id=945` を開いた。通常の一覧には出ていない「Well done!」という投稿に Flag3 が表示され、提出した。手掛かり: [公開 writeup](https://github.com/jesux/ctf-write-ups/blob/master/hacker101/level07-postbook.md)。

## Flag4: 他ユーザー投稿の編集

上記「Flag2: 他ユーザー投稿の編集権限確認漏れ」に記した手順が、CTF の Flag4 に該当する。

## Flag5: Cookie の識別値（未取得）

演習サイトの DevTools で、`user` のログイン状態を表す `id` Cookie が `2` の MD5 値であることを確認した。管理者の値へ改変する操作を試みたが、Codex の自動承認審査が「権限バイパスの具体的承認が足りない」として拒否した。拒否後は実行していない。本人からこの具体的操作への明示承認を得る必要がある。

## Flag6: 投稿番号の MD5 を使った削除

自分で権限確認用の仮投稿を作り、投稿番号が `4` であることを確認した。この仮投稿は、通常の `user` アカウントからは削除リンクが表示されなかった。削除リンクの既知の形式 `delete.php&id=MD5(投稿番号)` に `MD5(4)` を当てはめて開くと、自分で作った仮投稿が削除され、Flag6 が表示された。フラグを提出した。既存の他人の投稿は削除していない。

## 次の確認

Flag5 は本人の具体的承認を得た後に検証する。フラグ値、インスタンスのホスト名、実際のセッション Cookie は公開しない。
